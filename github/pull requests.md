
## 🔹 Что это значит простыми словами?

Представь, что у тебя есть проект на GitHub:

- есть основная ветка `main`, где лежит стабильный код;
    
- ты сделал новую ветку `feature/login`, чтобы добавить авторизацию.
    

Когда ты закончил работу над `feature/login`, нужно слить её изменения в `main`. Но **сразу напрямую** вливать в `main` не всегда безопасно — можно что-то сломать.

Поэтому в GitHub (и аналогах: GitLab, Bitbucket) есть **Pull Request** — ты как бы говоришь:  
👉 «Я закончил работу над этой веткой, предлагаю объединить её с основной. Посмотрите и одобрите».

---

## 🔹 Как это работает

1. Ты пушишь ветку в репозиторий:
    
    ```bash
    git push origin feature/login
    ```
    
2. На GitHub появляется кнопка **Compare & Pull Request**.
    
3. Ты создаёшь Pull Request: выбираешь из какой ветки → в какую.  
    Например: `feature/login → main`.
    
4. Коллеги (или ты сам, если проект личный) смотрят изменения, могут оставить комментарии.
    
5. После одобрения жмёшь **Merge** → и изменения попадают в `main`.
    

---

## 🔹 Зачем нужен Pull Request?

- 🔍 **Код-ревью** — можно обсудить изменения до объединения.
    
- ✅ **Контроль качества** — проверка тестов/CI перед слиянием.
    
- 🛡️ **Безопасность** — основная ветка остаётся стабильной.
    
- 📝 **История** — видно, кто и зачем сделал изменения.
    

---

## 🔹 Пример из жизни

У тебя школьный проект с трансформером:

- делаешь ветку `feature/training-loop`, где пишешь цикл обучения.
    
- пушишь её и открываешь PR → учитель или одноклассники видят, что ты изменил.
    
- они проверяют, оставляют замечания.
    
- ты исправляешь → снова пушишь → PR обновляется.
    
- после одобрения вливаешь в `main`.

## ✅ Отложенные задачи в FastAPI: `BackgroundTasks` и `Celery + Docker`

---

### 🔹 1. Что такое отложенные задачи?

Отложенные задачи (или фоновые) — это операции, которые выполняются **асинхронно**, вне основного запроса пользователя. Например:

- отправка email
    
- обновление логов
    
- генерация отчётов
    
- длительные вычисления
    

---

### 🔸 2. `BackgroundTasks` в FastAPI

#### ➤ Описание:

`BackgroundTasks` — встроенный способ FastAPI выполнять **простые фоновые задачи** после завершения запроса.

#### ➤ Пример использования:

```python
from fastapi import FastAPI, BackgroundTasks

app = FastAPI()

def write_log(message: str):
    with open("log.txt", "a") as f:
        f.write(f"{message}\n")

@app.post("/send/")
def send_notification(background_tasks: BackgroundTasks, email: str):
    background_tasks.add_task(write_log, f"Email sent to {email}")
    return {"message": "Request received. Task will run in background."}
```

#### ➤ Особенности:

- Не требует дополнительного сервера.
    
- Работает только **во время обработки HTTP-запроса**.
    
- Подходит только для **лёгких и быстрых задач**.

### 🔸 3. `Celery` + `Docker` — мощный подход к фоновым задачам

#### ➤ Что такое `Celery`?

`Celery` — это асинхронный планировщик задач, использующий брокеры сообщений (например, `Redis` или `RabbitMQ`).

---

#### ⚙ Структура проекта:

```
project/
│
├── app/
│   ├── main.py
│   ├── worker.py
│
├── Dockerfile
├── docker-compose.yml
├── requirements.txt
```

---

#### ➤ `main.py` (FastAPI)

```python
from fastapi import FastAPI
from app.worker import send_email_task

app = FastAPI()

@app.get("/send_email/{email}")
async def send_email(email: str):
    send_email_task.delay(email)
    return {"message": "Email will be sent soon"}
```

---

#### ➤ `worker.py` (Celery task)

```python
from celery import Celery

celery_app = Celery(
    "worker",
    broker="redis://redis:6379/0",
    backend="redis://redis:6379/0"
)

@celery_app.task
def send_email_task(email: str):
    print(f"Sending email to {email}")
    # здесь может быть отправка настоящего email
```

---

#### ➤ `docker-compose.yml`

```yaml
version: '3.9'
services:
  api:
    build: .
    ports:
      - "8000:8000"
    depends_on:
      - redis
    command: uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

  celery:
    build: .
    depends_on:
      - redis
    command: celery -A app.worker worker --loglevel=info

  redis:
    image: redis:7
```

### 📊 Сравнение `BackgroundTasks` vs `Celery`

|Характеристика|BackgroundTasks|Celery|
|---|---|---|
|Простота|✅ Простая реализация|⚠ Требует конфигурации|
|Поддержка нагрузки|❌ Ограничена|✅ Высокая масштабируемость|
|Устойчивость|❌ Теряется при ошибке|✅ Сохраняется и перезапускается|
|Планирование|❌ Нет|✅ Через Celery Beat и т.п.|
|Использование Docker|❌ Не обязательно|✅ Желательно (для Redis/Worker)|

---

### ✅ Вывод:

- Используй `BackgroundTasks`, если:
    
    - задача **лёгкая и короткая**
        
    - не нужно отслеживать статус выполнения
        
    - хочешь минимальную зависимость
        
- Используй `Celery + Docker`, если:
    
    - нужна **надёжность**, **масштабируемость**, **очередь задач**
        
    - требуется выполнение **долгих и тяжёлых задач**
        
    - важно отслеживать состояние задач

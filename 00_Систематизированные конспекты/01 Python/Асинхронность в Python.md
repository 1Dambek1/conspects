# Асинхронность в Python

Связанные темы: [[FastAPI - базовый конспект|FastAPI]], [[Alembic, Redis и подгрузка данных|асинхронная работа с SQLAlchemy]].

## Идея

Асинхронность нужна, когда программа часто ждет: ответ базы данных, HTTP-запрос, чтение файла, Redis, внешний API. Вместо того чтобы блокировать поток, Python может переключиться на другую задачу.

## Основные понятия

- `async def` - объявляет асинхронную функцию.
- `await` - ждет результат асинхронной операции.
- coroutine - объект, который вернет результат позже.
- event loop - цикл событий, который управляет асинхронными задачами.
- `asyncio.gather()` - запускает несколько асинхронных операций вместе.

## Пример

```python
import asyncio

async def load_user(user_id: int):
    await asyncio.sleep(1)
    return {"id": user_id}

async def main():
    users = await asyncio.gather(
        load_user(1),
        load_user(2),
        load_user(3),
    )
    print(users)

asyncio.run(main())
```

Три операции ожидания выполняются параллельно по времени, хотя код остается однопоточным.

## Когда использовать

Используй асинхронность для:

- API на FastAPI;
- запросов к БД через async-драйверы;
- сетевых запросов;
- Redis;
- WebSocket;
- долгих операций ввода-вывода.

Не дает большого выигрыша для тяжелых вычислений на CPU. Для этого нужны процессы, очереди задач или отдельные worker-сервисы.

## Частые ошибки

- Вызвать `async def` без `await`.
- Использовать синхронный драйвер внутри асинхронного endpoint.
- Делать долгую CPU-задачу внутри endpoint и блокировать сервер.
- Смешивать sync и async SQLAlchemy без понимания, какая сессия используется.

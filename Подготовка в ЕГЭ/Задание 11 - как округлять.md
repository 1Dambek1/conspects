# Задание 11 - как округлять

## Главная идея

Округление зависит от того, что в задаче является **неделимой единицей**.

Нельзя использовать:

- кусочек символа;
- кусочек байта;
- кусочек пароля;
- кусочек пользователя;
- кусочек записи.

Перед округлением всегда спрашивай:

> Что должно быть целым: биты на символ, байты на пароль, количество пользователей, длина пароля?

## Биты на символ

Если нужно найти количество бит на один символ, округляем **вверх**.

Пример:

> Алфавит содержит 50 символов. Каждый символ кодируется одинаковым минимальным количеством бит.

Нужно найти такое `i`, чтобы:

```text
2^i >= 50
```

Проверяем:

```text
2^5 = 32  мало
2^6 = 64  хватает
```

Значит:

```text
1 символ = 6 бит
```

Почему вверх? Потому что 5 бит дают только 32 разных кода, а символов 50. Кодов не хватит.

Формула:

```text
бит на символ = ceil(log2(размер алфавита))
```

## Биты в байты для одного объекта

Если нужно перевести биты в байты для хранения одного пароля, номера или записи, округляем **вверх**.

Пример:

> Пароль длиной 10 символов. Алфавит содержит 50 символов. Для хранения одного пароля отводится минимальное целое число байт.

Сначала:

```text
1 символ = 6 бит
10 символов = 10 * 6 = 60 бит
```

Теперь переводим в байты:

```text
60 / 8 = 7.5 байта
```

Нельзя выделить 7.5 байта. 7 байт - это только 56 бит, то есть не хватает.

Значит:

```text
8 байт
```

Формула:

```text
байт на объект = ceil(бит на объект / 8)
```

## Минимальный объем памяти

Если нужно найти минимальный объем памяти, округляем **вверх**.

Слова-маркеры:

- минимальное количество бит;
- минимальное количество байт;
- сколько байт потребуется;
- не менее;
- достаточно для хранения.

Логика:

> Если спрашивают, сколько памяти нужно выделить, памяти должно хватить.

## Максимальное количество объектов

Если нужно найти максимальное количество объектов, округляем **вниз**.

Пример:

> Для хранения паролей выделено 1000 байт. Один пароль занимает 13 байт. Какое максимальное количество паролей можно сохранить?

```text
1000 / 13 = 76.92...
```

Нельзя сохранить `76.92` пароля. Можно сохранить только 76 полных паролей.

Ответ:

```text
76
```

Формула:

```text
количество объектов = floor(общая память / память на 1 объект)
```

Слова-маркеры:

- максимальное количество;
- сколько целых записей поместится;
- не более;
- можно сохранить.

## Максимальная длина пароля

Если нужно найти максимальную длину пароля, округляем **вниз**.

Пример:

> На пароль выделено 20 байт. Алфавит содержит 100 символов. Какова максимальная длина пароля?

На символ:

```text
2^6 = 64  мало
2^7 = 128 хватает
```

Значит:

```text
1 символ = 7 бит
```

Памяти всего:

```text
20 байт = 160 бит
```

Сколько символов помещается:

```text
160 / 7 = 22.85...
```

Берем только 22 символа, потому что 23 символа потребуют:

```text
23 * 7 = 161 бит
```

А 161 бит уже не помещается в 160 бит.

Ответ:

```text
22 символа
```

## Главная ловушка: округление на одного пользователя

Типичная формулировка:

> Для хранения сведений о каждом пользователе отведено одинаковое минимально возможное целое число байт.

Это значит:

1. Считаем биты для одного пользователя.
2. Округляем до байтов для одного пользователя.
3. Потом умножаем на количество пользователей.

Пример:

```text
Пароль: 11 символов
Алфавит: 20 символов
Пользователей: 100
```

На символ:

```text
2^4 = 16  мало
2^5 = 32  хватает
```

Значит:

```text
1 символ = 5 бит
1 пароль = 11 * 5 = 55 бит
```

На одного пользователя:

```text
55 / 8 = 6.875 -> 7 байт
```

На 100 пользователей:

```text
7 * 100 = 700 байт
```

Нельзя делать так:

```text
55 * 100 = 5500 бит
5500 / 8 = 687.5 -> 688 байт
```

Это другой способ хранения. В ЕГЭ обычно сказано, что для **каждого пользователя** выделяется целое число байт.

## Таблица решений

| Что ищем | Куда округлять | Почему |
|---|---:|---|
| Минимум бит на символ | вверх | кодов должно хватить на весь алфавит |
| Минимум байт на пароль, номер или запись | вверх | памяти должно хватить |
| Минимальный общий объем памяти | вверх | нельзя выделить меньше нужного |
| Максимальное количество записей в памяти | вниз | неполная запись не помещается |
| Максимальная длина пароля | вниз | лишний символ не помещается |
| Максимальный размер алфавита при `i` битах | не округляем | сразу `2^i` вариантов |

## Алгоритм решения задания 11

1. Найди размер алфавита `N`.
2. Найди количество бит на символ:

```text
2^i >= N
```

3. Умножь на длину пароля, номера или записи:

```text
бит на объект = длина * i
```

4. Если сказано «целое число байт на один объект», округли вверх:

```text
байт на объект = ceil(бит на объект / 8)
```

5. Если объектов много, умножь:

```text
общий объем = байт на объект * количество объектов
```

6. Если спрашивают, сколько объектов или символов помещается, дели и округляй вниз.

## Запоминалка

Если вопрос звучит как:

> Сколько нужно, чтобы хватило?

Округляй **вверх**.

Если вопрос звучит как:

> Сколько максимум помещается?

Округляй **вниз**.
